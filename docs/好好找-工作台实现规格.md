# 好好找工作台实现规格

## 问题陈述
确认过的交互原型需要支持可持续使用的练习、录音复盘、简历、模型配置和账户邀请。

## 解决方案
保留原型的三栏工作台、题单确认、手动控制录音和追问、六维证据报告与单轮重答。以 React、Vite、TypeScript 和 Express 交付，用本地 JSON 与文件保存工作台。大模型选 GPT-4o，转写选阿里云 Paraformer 实时识别接口，手动录音结束后提交音频。现存旧练习与认证数据兼容保留。

## 用户故事
1. 求职者可以提交 JD 并生成题单。
2. 求职者可以手动输入原题并调整顺序。
3. 求职者可以导入公开小红书链接，失败时按序提交截图。
4. 求职者可以核对截图原文和题目候选，然后开练。
5. 求职者可以手动录音、回听、输入作答和推进。
6. 求职者可以根据当前作答主动生成一道追问。
7. 求职者可以结束练习，即使还有未完成的转写。
8. 求职者可以先检查六维证据覆盖，再补答或按 60 分计入缺项。
9. 求职者可以读取整场六维评分并定位作答证据。
10. 求职者可以输入想改善的点，取得单轮框架和手动重答。
11. 求职者可以采用唯一认可的新版并手动重评。
12. 求职者可以导入真实录音，校对说话人、问答和时间戳，一次确认。
13. 求职者可以选择适合本场的简历。
14. 受邀者可以独立配置模型与语音服务并承担费用。
15. 管理员可以邀请和管理账户，每个账户只访问自己的工作台和媒体。

## 实现决策
工作台保存独立账户的草稿与报告，原声保存在本地文件。单实例原子写入 JSON。服务端加密用户模型密钥，API 响应只提供是否已配置。模型输出作为建议，确认、默认分和总分由应用处理。保留旧录音页面和数据库兼容入口。

## 测试决策
通过原型对应的浏览器入口和 HTTP 接口验证题单、原声持久化、确认、覆盖补答、报告与账户隔离。无用户密钥时使用可控上游验证服务边界，真实计费服务单列验收。

## 范围外
实时双向语音问答、逐题即时评分、开放注册和部署者共享计费密钥。
